# itcoolmcplang1c

MCP-сервер, который отдаёт AI-ассистентам справку встроенного языка
1С:Предприятие: объекты и их свойства, методы с параметрами и примерами,
разделы встроенного языка, общих правил языка и языка запросов.

Ассистент перестаёт выдумывать сигнатуры: вместо «кажется, у `ТаблицаЗначений`
есть такой метод» он спрашивает сервер и получает описание из справки той
платформы, которая установлена у вас.

## Справка не покидает вашу машину

**База знаний собирается на вашем компьютере из вашей собственной установки
платформы 1С и никуда не передаётся.** В этом репозитории её нет и не будет: ни
одного файла справки, ни одного производного от неё байта. Репозиторий содержит
только код — распаковщик контейнера `.hbk` и разбор страниц справки.

Собранный индекс кэшируется локально (`%LOCALAPPDATA%\itcoolmcplang1c` на
Windows, `~/.cache/itcoolmcplang1c` на Linux) и наружу не уходит.

## Быстрый старт

Нужны Rust 1.75 или новее и установленная платформа 1С:Предприятие.

```sh
git clone https://github.com/itcoollook-ru/itcoolmcplang1c
cd itcoolmcplang1c
cargo build --release --locked
```

Флаг `--locked` не косметика: в репозитории лежит `Cargo.lock`, подобранный под
MSRV 1.75. Без него свежий cargo волен обновить зависимости до версий, которым
нужен компилятор новее.

Бинарник окажется в `target/release/itcoolmcplang1c` (на Windows — `.exe`).

### 1. Собрать базу знаний

```sh
# автопоиск установленной платформы
target/release/itcoolmcplang1c index

# либо явно
target/release/itcoolmcplang1c index --platform-dir "C:\Program Files\1cv8\8.3.27.1936\bin"
```

Разбор справки занимает секунды — это разовая цена. Результат ложится в
кэш, и дальше сервер стартует мгновенно. Кэш пересобирается сам, когда вы
обновляете платформу.

Автопоиск смотрит в `C:\Program Files\1cv8\<версия>\bin` (Windows) и
`/opt/1cv8/x86_64/<версия>` (Linux); при нескольких установленных версиях берёт
старшую.

Этот шаг необязателен: если базы нет, сервер соберёт её сам при первом запуске,
фоном. Пока сборка идёт, инструменты отвечают текстом «идёт индексация, N%», а
не пустой выдачей — так ассистент понимает, что нужно повторить запрос, и не
делает вывод «такого метода в платформе нет».

### 2. Проверить установку

```sh
target/release/itcoolmcplang1c --check
```

Одна команда отвечает на вопрос «почему у меня не работает»: печатает версию
сервера, найденный каталог платформы и её версию, какие книги справки открыты и
сколько в них разделов, откуда взялся индекс — из кэша или собран заново — и
сколько это заняло, числа базы (объекты, методы, свойства) и результат
тестового поиска. Последняя строка — вердикт. Если что-то не так, пункт
печатается с причиной и с тем, что сделать, а код возврата — `1`.

### 3. Подключить к MCP-клиенту

Claude Desktop, `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "itcoolmcplang1c": {
      "command": "C:\\путь\\к\\itcoolmcplang1c.exe",
      "args": ["--platform-dir", "C:\\Program Files\\1cv8\\8.3.27.1936\\bin"]
    }
  }
}
```

Сервер говорит по MCP через stdio и запускается хостом как дочерний процесс.
Аргументы задаются раздельной формой (`--platform-dir <путь>`); флаги
самосборки понимают и форму `--platform-dir=<путь>`.

Проверить вручную, без клиента:

```sh
printf '%s\n%s\n' \
  '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"probe","version":"1"}}}' \
  '{"jsonrpc":"2.0","id":2,"method":"tools/list"}' \
  | target/release/itcoolmcplang1c
```

## Инструменты

| Инструмент | Что делает |
|---|---|
| `search_1c_docs` | Поиск по справке: объекты, методы, разделы языка. Фильтры по версии платформы и контексту исполнения (клиент/сервер) |
| `get_method_details` | Карточка метода: параметры, возвращаемое значение, примеры, примечания |
| `find_usage_examples` | Примеры кода, где встречается объект или метод |
| `list_versions` | Какие версии документации загружены |
| `server_info` | Версия сервера и наполнение базы знаний |

## Ключи запуска

| Ключ | Назначение |
|---|---|
| `index` | Собрать индекс и выйти (прогрев до подключения клиента) |
| `--platform-dir <PATH>` | Каталог `bin` установки платформы; иначе автопоиск |
| `--help-lang <ru\|en>` | Язык справки: `ru` → `sh*_ru.hbk`, `en` → `sh*_root.hbk` |
| `--platform-version <V>` | Версия платформы, когда её не видно из пути |
| `--data-dir <PATH>` | Каталог с готовым индексом (JSON). Если он там есть, платформа не читается |
| `--out <PATH>` | Только для `index`: выгрузить базу знаний в JSON |
| `--log-level <LEVEL>` | `trace`, `debug`, `info`, `warn`, `error` |
| `--config <PATH>` | Путь к `itcoolmcplang1c.toml` |
| `--check` | Проверить установку и выйти: платформа, справка, индекс, числа, тестовый запрос |
| `--version`, `--help` | Версия сборки, справка |

Тонкие настройки (ранжирование поиска, формат журнала) живут в
`itcoolmcplang1c.toml` — шаблон лежит в репозитории. Приоритет по каждому ключу
отдельно: аргумент > переменная окружения > файл > значение по умолчанию.

## Как это устроено

`.hbk` — контейнер формата 1С. Внутри него элемент `FileStorage` — обычный ZIP
со страницами справки в HTML. Сервер разбирает контейнер, читает страницы и
раскладывает их в схему базы знаний:

* `shcntx_ru.hbk` — объекты, свойства, методы, конструкторы;
* `shlang_ru.hbk` — встроенный язык;
* `shclang_ru.hbk` — общие правила языка;
* `shquery_ru.hbk` — язык запросов.

Отсутствие любой из трёх последних книг — не отказ: база собирается из того, что
есть. Два прогона на одной платформе дают идентичный результат.

**Русская справка полнее английской.** С `--help-lang en` берутся файлы
`sh*_root.hbk`, и разбор идёт по английским заголовкам разделов — методы,
параметры, примеры и разделы языка извлекаются полностью. Но объектов и их
свойств выходит меньше: в русской справке страница объекта отличается от
страницы-рубрики каталога английским именем в скобках
(«ТаблицаЗначений (ValueTable)»), а в английской скобок нет ни у той, ни у
другой, и часть объектов остаётся неотличима от рубрик. Если нужна полная база —
берите `ru` (значение по умолчанию).

## Обратная связь

Об ошибках — в Issues репозитория. Проект публикуется как есть: ответ и
исправление возможны, но не гарантированы сроком. Файлы справки и фрагменты
её содержимого к сообщениям прикладывать не нужно — для разбора хватает
вывода `--check` и текста ошибки.
